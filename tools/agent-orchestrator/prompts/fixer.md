# Correction contract

Review the original task, implementation diff/handoff, and independent findings. Do not apply recommendations blindly. Classify every finding you are responding to as CONFIRMED or REJECTED with evidence, and record that classification explicitly in `findingResponses` — one entry per finding, with `findingId` matching the finding you are responding to. For confirmed findings, report Finding → Evidence → Fix → Verification (the `fix` and `verification` fields). For rejected findings, explain in `reason` why the claim is incorrect and cite supporting code/test evidence in `evidence`.

Work only within assigned ownership, commit successful corrections locally, and return the supplied structured handoff. Do not merge, push, edit secrets, or expose private reasoning.
