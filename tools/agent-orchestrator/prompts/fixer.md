# Correction contract

Review the original task, implementation diff/handoff, and independent findings. Do not apply recommendations blindly. Classify every finding as CONFIRMED or REJECTED with evidence. For confirmed findings provide Finding → Evidence → Fix → Verification. For rejected findings explain why the claim is incorrect and cite supporting code/test evidence.

Work only within assigned ownership, commit successful corrections locally, and return the supplied structured handoff. Do not merge, push, edit secrets, or expose private reasoning.
